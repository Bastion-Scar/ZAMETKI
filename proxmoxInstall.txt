4. ИЗМЕНИТЬ HOSTNAME: SCAR -> PVE
============================================================

ВАЖНО:
Это нужно сделать ДО запуска Proxmox.

Устанавливаем новое имя:

hostnamectl set-hostname pve

Проверяем:

hostname

Должно вывести:

pve


Проверяем:

hostnamectl

Должно быть:

Static hostname: pve


============================================================
5. ПРОВЕРИТЬ /etc/hostname
============================================================

cat /etc/hostname

Должно вывести:

pve

Если там осталось:

scar

исправить:

echo pve > /etc/hostname


============================================================
6. НАСТРОИТЬ /etc/hosts
============================================================

Открываем:

nano /etc/hosts

Приводим файл к виду:

127.0.0.1 localhost
10.202.49.52 pve

::1 localhost ip6-localhost ip6-loopback
ff02::1 ip6-allnodes
ff02::2 ip6-allrouters


ВАЖНО:

Не должно оставаться старой записи вроде:

127.0.1.1 scar.utz.local scar


Главная строка:

10.202.49.52 pve

7. ПРОВЕРИТЬ HOSTNAME
============================================================

hostname

Результат:

pve


hostname -f

Результат:

pve


cat /etc/hostname

Результат:

pve

grep -R "scar" /etc/hostname /etc/hosts 2>/dev/null

Желательно, чтобы ничего не вывело.

8. ДОБАВИТЬ КЛЮЧ PROXMOX
============================================================

Для Debian 13:

wget https://enterprise.proxmox.com/debian/proxmox-archive-keyring-trixie.gpg \
-O /usr/share/keyrings/proxmox-archive-keyring.gpg


Проверить:

ls -l /usr/share/keyrings/proxmox-archive-keyring.gpg


============================================================
9. ДОБАВИТЬ PROXMOX REPOSITORY
============================================================

Создать файл:

nano /etc/apt/sources.list.d/pve-no-subscription.sources

Вставить:

Types: deb
URIs: http://download.proxmox.com/debian/pve
Suites: trixie
Components: pve-no-subscription
Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg


Сохранить файл.


============================================================
10. УДАЛИТЬ ENTERPRISE REPOSITORY
============================================================

Если подписки Proxmox нет, Enterprise repository
не нужен.

Проверить:

ls -la /etc/apt/sources.list.d/


Если существует:

pve-enterprise.sources

удалить:

rm -f /etc/apt/sources.list.d/pve-enterprise.sources


Проверить:

grep -R "enterprise.proxmox.com" \
/etc/apt/sources.list \
/etc/apt/sources.list.d/ 2>/dev/null


Если команда ничего не вывела —
Enterprise repository отключён.

16. НАСТРОИТЬ СЕТЬ PROXMOX
============================================================

Открыть:

nano /etc/network/interfaces


Полностью сделать:

auto lo
iface lo inet loopback

auto enp2s0
iface enp2s0 inet manual

auto vmbr0
iface vmbr0 inet static
    address 10.202.49.52/24
    gateway 10.202.49.2
    bridge-ports enp2s0
    bridge-stp off
    bridge-fd 0
    dns-nameservers 172.16.4.5 8.8.8.8


Схема:

enp2s0
   |
   v
 vmbr0
   |
   +--- Proxmox
   |
   +--- VM
   |
   +--- LXC


ВАЖНО:

IP:

10.202.49.52/24

находится на:

vmbr0

а не на:

enp2s0


============================================================
17. ПРИМЕНИТЬ СЕТЬ
============================================================

ifreload -a


Не рекомендуется без необходимости делать:

ifdown enp2s0

поскольку можно потерять сетевое соединение.

18. ПРОВЕРИТЬ IP
============================================================

ip addr show vmbr0


Должно быть:

10.202.49.52/24


Проверить маршрут:

ip route


Должно быть:

default via 10.202.49.2 dev vmbr0


============================================================
19. ПРОВЕРИТЬ СЕТЬ
============================================================

Проверить gateway:

ping -c 4 10.202.49.2


Проверить интернет:

ping -c 4 8.8.8.8


Проверить DNS:

ping -c 4 google.com


Все три проверки должны работать.

20. ПРОВЕРИТЬ PVE-CLUSTER
============================================================

systemctl status pve-cluster --no-pager


Нужно:

Active: active (running)


Если не запущен:

systemctl reset-failed pve-cluster

systemctl start pve-cluster


Проверить:

systemctl status pve-cluster --no-pager


============================================================
21. ЕСЛИ PVE-CLUSTER РУГАЕТСЯ НА SCAR
============================================================

Если появляется:

Unable to resolve node name 'scar'


Проверить:

hostname

hostname -f

cat /etc/hostname

cat /etc/hosts


Везде должно использоваться:

pve


В /etc/hosts:

10.202.49.52 pve


После исправления:

systemctl reset-failed pve-cluster

systemctl start pve-cluster


Проверить:

systemctl status pve-cluster --no-pager
